# 支出分析の分類辞書 — 運用手順（2026-09-05）

Zaim のレシート撮影は品目名から分類を**学習**するため、一度誤ると同じ品目が
毎回同じ誤りで入ってくる（実測: ごぼう→通信 が18回連続、スーパーのレシート1枚10行が
丸ごと交通、医療・保険に食料品115件）。明細画面の手動修正は**その行**にしか効かず、
翌月に同じ品目を買えば再発する。そこで**取り込み時に Zaim の分類より上で効く辞書**を持つ。

辞書は CSV で育てる。**CSV を直して取り込めば効く**（コマンドは不要）。

## 辞書は2つ

| 辞書 | ファイル | 何をするか | いつ効くか |
|---|---|---|---|
| 品目辞書 | `card_insight/label_rules.csv` | 品目名に語が含まれたら分類を差し替える（鶏→食費、いろはす→飲料…） | 取り込み時に自動で DB（`LabelRule`）へ upsert → 適用 |
| 定型句辞書 | `card_insight/nonfood_phrases.csv` | 交通/通信/教育・教養/遊びで**本物の行の文言**を列挙。当たらない商品行は食費に倒す | 取り込みのたびにファイルを直読み |

優先順位: **品目辞書 > 定型句辞書 > Zaim の分類 > 加盟店ルール（MerchantRule）**。
画面で直した `manual_*` は表示時にさらに上で効く（人が直したものは常に勝つ）。

## 品目辞書（label_rules.csv）の書き方

```csv
priority,pattern,category,subcategory,note
10,氷結|ビール|ハイボール|ウイスキー,飲料,酒,酒類。飲み物は食費より先に判定
11,いろはす|エスセレクト|サントリー|コーヒー|牛乳|コーラ(?!ック),飲料,ジュース,清涼飲料
100,鶏|豚|牛肉|鮮魚|ちりめん,食費,食料品,肉・魚
100,椎茸|しいたけ|しめじ|キャベツ|トマト,食費,食料品,野菜・きのこ
```

- `pattern` は**正規表現・部分一致**。`|` で複数の語をまとめられる
- `priority` は**小さいほど先**に評価され、最初に当たったルールで決まる。
  飲み物は食べ物の語と重なりやすい（「コーヒーゼリー」等）ので飲料を先（10〜11）にしてある
- `subcategory` は**必ず入れる**。空にすると Zaim の内訳（「電車」「消耗品」等）がそのまま残り、
  「飲料/電車」のような組み合わせになる
- 対象は**商品行だけ**。外税・割引・レジ袋（レシート付随行）には当てない
  （正しい分類はレシート次第で、品目名だけでは決まらない）

### 語を足すときの罠（実際に踏んだ）
- **`コーラ` → 下剤「コーラック」に当たる**。`コーラ(?!ック)` で除外
- **`パン` → 「パンパース」に当たる**。入れない（食パンは「食パン」で拾う）
- 短い語ほど誤爆する。`米` は「米国」、`酢` は「酢酸」に当たりうる。2文字以上の語か、
  前後を限定した表現にする
- 語を足したら取り込み後に**明細で「分類の出どころ＝品目ルールで訂正」に絞って目視**する

## 定型句辞書（nonfood_phrases.csv）の書き方

```csv
category,pattern,note
交通,定期|ICOCA|Suica|チャージ|切符|新幹線|タクシー|バス|高速|駐車|ガソリン,交通で本物の行に出る定型句
通信,Apple|APPLE|Google|Microsoft|ConoHa|SIM|Wi-?Fi|Prime|Netflix,通信で本物の行に出る定型句
```

- 発想（ユーザー発案）: 交通・通信・教育・遊びは**本物の行がほぼ定型文言**なのに対し、
  そこに紛れる不明な行はほぼ食料品。なら本物の文言を列挙し、それ以外を食費にする方が、
  食べ物の語を全部列挙するより漏れが少ない
- **本物の行を食費にされたら、その文言をこの辞書に足す**（例: 新しいサブスク名）
- ⚠️ **医療・保険／健康／日用雑貨には適用しない**（`DEFAULT_FOOD_CATEGORIES`）。
  ドラッグストアのレシートは薬と食品が本当に混ざるので、読めない行を食費に倒すと薬を食費にする。
  ここは品目辞書で拾う

## 反映手順

```bash
# ローカル: CSV を編集 → 取り込み（画面の「再取込」でも同じ）
./venv/Scripts/python.exe manage.py shell -c "from spending import services; print(services.import_from_files().message)"

# サーバー: pull して再取込するだけ
cd /srv/web_analize && git pull
./venv/bin/python manage.py shell -c "from spending import services; print(services.import_from_files().message)"
```

- 取り込み時の自動同期は **CSV を正として追加・更新・削除**する（CSV に無い pattern は DB からも消える）。
  ⚠️ **pattern は主キー**。pattern の文字列を書き換えると「新ルール追加＋旧ルール削除」になる。
  削除しない設計にしていた時期は、旧 pattern の行が DB に残って効き続け、除外を足したのに
  効かない事故が起きた（味ぽん500ml が飲料のままだった）。DB に手で足したルールは
  次の取り込みで消えるので、**ルールは必ず CSV に書く**
- `sync_label_rules` コマンドは手動で同期したいときの補助（`--dry-run` で差分確認）
- 取り込みメッセージに件数が出る。変わらないときは CSV の文字コード（UTF-8）と
  ヘッダー行（`priority,pattern,category,subcategory,note`）を疑う

## 辞書に無い誤りの見つけ方

支出分析トップの **「Zaimの誤分類の疑い」** カードに2種の検出が出る（自動では直さない）:

1. **同じ品目が割れている** — 同じ品目名が食費と別カテゴリに分かれている（Zaim の誤学習）
2. **レシートごと紛れた疑い** — 4行以上の商品行が非食料品カテゴリに並ぶ（＝食料品のレシート）

「明細 →」でその行に飛べる。直し方は2つ:
- **繰り返す品目** → 品目辞書に語を足す（今後の取り込みにも効く）
- **1回きり** → 明細でチェックを付けて「まとめて変更」（その行だけ）

## 検証（辞書を変えたら必ず）

取り込み後、次が変わっていないことを確認する。変わっていたら辞書が集計を壊している。

| 不変条件 | 値（2026-09-05） |
|---|---|
| 集計対象の合計 | ¥1,806,010 |
| Amazon 紐付き請求 | 63 件 |
| 手動修正の件数 | 減っていないこと |

辞書は分類を付け替えるだけで、金額・行数・突合には触らない。

## 根本対処

**Zaim アプリ側でその品目の分類を一度直す**と学習し直し、以後の撮影から正しく付く。
辞書はその保険で、Zaim を直しても残しておいて害はない。
